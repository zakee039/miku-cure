# Miku Cure v1.2.2 Live2D 追踪 UI、编辑模式与镜像肢体追踪修复方案

> 日期：2026-09-01
> 施工基线：`v1.2.2` / `84fcabc`
> 项目：`E:\project\miku cure`
> 状态：代码施工完成，真人初验完成；已按反馈修正左右眼、歪嘴与启动追踪时序，待复验
> 本方案只施工“肢体追踪”中的现有面部 feature，不包含上肢 feature；上肢扩展见独立方案 `20260901-v1.2.2-肢体追踪扩展-上肢姿态方案.md`。

---

## 1. 改造目标

v1.2.2 已完成 Live2D 鼠标追踪、Face Landmarker 连续面捕、精细表情参数、面捕失效 3 秒后回退鼠标等基础能力。本轮不重新设计追踪架构，而是修正当前实机验收中发现的 3 类问题：

1. 模型编辑 UI 混乱：水印按钮与鼠标/面捕按钮样式不统一，状态文字位置不合理；
2. 进入模型编辑后，当前代码会把追踪仲裁器整体置为 `none`，导致首页可面捕、编辑模式却显示未检测到人脸；
3. 当前“肢体追踪”的面部 feature 方向不符合用户直觉，需要统一为**照镜子式反应**，且两个 Live2D 模型采用完全一致的镜像规则。

本轮必须保持 v1.2.2 已确认的产品约束：

- 表情识别与肢体追踪是两条独立链路；
- 鼠标追踪与肢体追踪是两个独立模型特性开关；
- 鼠标追踪默认开启，肢体追踪默认关闭；
- 肢体追踪中当前可用的面部 feature 有效时，头眼面部参数的实际驱动优先级高于鼠标；
- 当前面部 feature 连续失效 **3 秒** 后，若鼠标追踪开启，则头眼面部参数实际驱动回退鼠标；
- 面部 feature 重新稳定后自动切回肢体追踪；
- 不恢复 `autoInteract: true`，继续使用 Miku Cure 自己的追踪仲裁器。

## 2. 当前问题定位

### 2.1 UI 混用两套按钮体系

当前 `frontend/3d_runtime.js` 中：

- 鼠标追踪和面捕由 `createTrackingButton()` 创建，使用 `character-model-button`；
- 水印仍使用独立的 `character-watermark-toggle` 大文字按钮，并动态显示“恢复水印/去除水印”；
- `character-tracking-status` 目前按 `activeTrackingSource` 显示，所以进入编辑模式后经常出现“当前追踪：关闭”。

这会导致模型编辑区域出现按钮大小、文案和状态表达不一致的问题。

### 2.2 编辑模式主动禁用了追踪

当前 `frontend/3d_runtime.js` 的两个关键限制为：

```js
syncMouseTrackingSubscription() {
  ...
  && !adjustmentEnabled
  ...
}
```

以及：

```js
function resolveTrackingSource(now) {
  let next = 'none';
  if (!adjustmentEnabled) {
    // face / mouse 仲裁
  }
}
```

因此：

```text
进入模型编辑
→ adjustmentEnabled = true
→ face 与 mouse 均不参与仲裁
→ activeTrackingSource = none
```

这就是“首页能正常面捕，但进入模型编辑后显示未检测到人脸/关闭”的直接原因，并非 Face Landmarker、摄像头或模型失效。

### 2.3 当前面部 feature 的方向是坐标映射问题，不是识别问题

Face Landmarker 已能正确提供头姿、双眼、眉毛和嘴部语义数据；当前视觉方向错误来自：

- 摄像头输入坐标系；
- Face Landmarker 头姿坐标系；
- Live2D 参数正负方向；
- 左/右眼、左/右眉的“解剖学左右”与屏幕左右；
- 模型本身参数方向。

本轮不在多个地方零散翻符号，而是建立**统一镜像语义层**。

## 3. 最终 UI 定义

### 3.1 三个按钮统一为纯 Emoji 小图标

模型编辑状态下，左侧靠底部纵向排列三个按钮，顺序固定为：

```text
🖼️  水印
🖱   鼠标追踪
🫣   肢体追踪
```

界面上**只显示 Emoji，不显示按钮文字**。功能名与状态通过 `title` / `aria-label` 提供。

推荐结构：

```text
┌────────────────────────────────────┐
│ 左键拖拽，滚轮缩放             ✕  │
│                                    │
│                Miku                │
│                                    │
│ 🖼️                                 │
│ 🖱                                  │
│ 🫣                 当前追踪：肢体追踪 │
└────────────────────────────────────┘
```

### 3.2 左下纵向布局

三个按钮放入统一容器，例如：

```html
<div class="character-edit-feature-buttons">
  <!-- watermark / mouse / face -->
</div>
```

CSS 目标：

- `position: absolute`；
- 靠模型编辑区域左侧；
- 靠底部排列；
- `display: flex`；
- `flex-direction: column`；
- 三个按钮相同宽高、圆角、背景、hover、active 风格；
- 不再保留当前“恢复水印”大按钮。

具体像素可按现有窗口比例微调，但三个按钮必须视觉一致，且不得遮挡模型主要脸部区域。

### 3.3 关闭状态统一叠加红色斜线

三个 Emoji 都使用完全一致的开关表达：

| 功能 | 开启 | 关闭 |
|---|---|---|
| 水印 | `🖼️` 正常显示 | `🖼️` 上叠加红色斜线 |
| 鼠标追踪 | `🖱` 正常显示 | `🖱` 上叠加红色斜线 |
| 肢体追踪 | `🫣` 正常显示 | `🫣` 上叠加红色斜线 |

**不要**寻找或拼接“带删除线 Emoji”，也不要把 `/` 字符直接塞进按钮文字。不同 Windows/Emoji 字体下这种做法对齐不稳定。

推荐使用 CSS 伪元素：

```css
.character-model-button.is-off::after {
  content: '';
  position: absolute;
  left: 18%;
  right: 18%;
  top: 50%;
  height: 2px;
  background: #ff5b5b;
  transform: rotate(-45deg);
  transform-origin: center;
  pointer-events: none;
}
```

按钮需要 `position: relative`。最终红线应从 Emoji 左下向右上或左上向右下斜穿均可，但三个按钮必须方向一致。

### 3.4 水印按钮的逻辑语义必须翻正

当前代码内部变量是：

```js
hideModelWatermark
```

该变量为 `true` 时表示“隐藏水印”。但新的 UI 按钮表达的是“水印功能是否开启”。因此 UI 状态必须按：

```text
watermarkEnabled = !hideModelWatermark
```

定义：

- 水印可见 → `🖼️` 无红线；
- 水印隐藏 → `🖼️` 有红线。

不能直接继续把 `hideModelWatermark` 当作 `aria-pressed`，否则视觉语义会反过来。

### 3.5 鼠标与肢体追踪按钮状态

鼠标：

```text
preference.mouseEnabled === true  → 正常 🖱
preference.mouseEnabled === false → 红线 🖱
```

肢体追踪：

```text
preference.bodyEnabled === true  → 正常 🫣
preference.bodyEnabled === false → 红线 🫣
```

肢体追踪内部的面部 feature 临时丢脸、初始化中或摄像头异常时，**不要给 Emoji 加红线**，因为用户并没有关闭肢体追踪。

这些运行时信息放在 `title` 中，例如：

```text
肢体追踪：开启
肢体追踪：开启（摄像头初始化中）
肢体追踪：开启（暂时未检测到人脸，3 秒后回退鼠标）
肢体追踪：开启（当前由鼠标回退）
```

### 3.6 “当前追踪”移动到右下角

`character-tracking-status` 移到模型编辑区域**右下角**，使用弱提示文字，不再占据左侧按钮区域。

显示逻辑按用户选择的模型特性，而不是 `activeTrackingSource`：

```text
bodyEnabled === true
→ 当前追踪：肢体追踪

bodyEnabled === false && mouseEnabled === true
→ 当前追踪：鼠标追踪

bodyEnabled === false && mouseEnabled === false
→ 当前追踪：关闭
```

这意味着：

- 肢体追踪开启但面部 feature 正在 3 秒容错期：仍显示“当前追踪：肢体追踪”；
- 肢体追踪开启且面部 feature 已实际回退鼠标：仍显示“当前追踪：肢体追踪”；
- 实际 fallback 状态只用于内部仲裁和按钮 tooltip，不把主状态文字改成“关闭”。

这样“当前追踪”表达的是**用户选择的主追踪模式**，不会因暂时丢脸、编辑状态或 400 ms 稳定窗口频繁跳字。

---

### 3.7 用户开关与内部 feature 的正式命名

从本方案开始，产品层不再使用“面部追踪”作为用户可见模型特性名称，统一为：

```text
bodyEnabled = 肢体追踪总开关
```

用户只看到一个 `🫣 肢体追踪` 按钮。该总开关负责启停当前模型已经支持的全部肢体追踪 feature。

当前 v1.2.2 已有能力仍作为内部 feature 保留：

```text
tracking.face      → Face Landmarker 面部 feature
```

未来若上肢方案的模型参数 Gate 通过，则同一总开关下增加：

```text
tracking.upperBody → Pose Landmarker 上肢 feature
```

**`tracking.face` / `tracking.upperBody` 是模型能力模块，不是两个用户开关。上肢 feature 不增加独立按钮。**

持久化配置把现有每模型 `faceEnabled` 正式迁移为 `bodyEnabled`。为了保持已经发布的 v1.2.2 用户选择，首次读取允许：

```text
bodyEnabled ?? legacy faceEnabled
```

读到旧字段后按新结构保存，后续只写 `bodyEnabled`。内部 Face Landmarker 的健康度、丢脸时间和错误原因仍可继续使用 `face*` / `faceFeature*` 命名，因为它们描述的是具体 feature，而不是产品总开关。

## 4. 编辑模式必须保持追踪可用

### 4.1 不再把 `adjustmentEnabled` 当作追踪总开关

修改 `resolveTrackingSource(now)`：

当前：

```text
adjustmentEnabled = true
→ next 永远为 none
```

改造后：

```text
adjustmentEnabled 与追踪仲裁无关
```

即进入模型编辑后仍然正常执行：

```text
有效面捕 > 鼠标追踪 > none
```

并继续维持：

```text
面捕连续失效 < 3 秒 → 保持 face
面捕连续失效 >= 3 秒 → mouseEnabled 时回退 mouse
面捕重新稳定约 400 ms → 自动切回 face
```

### 4.2 肢体追踪的面部 feature 在拖动/缩放模型时也不关闭

面部 feature 不依赖鼠标位置，因此：

- 进入编辑模式：不停面部 feature；
- 左键拖模型：不停面部 feature；
- 滚轮缩放：不停面捕；
- 松开鼠标：无需重新启动 Face Landmarker；
- 摄像头实例不因编辑模式切换而释放/重开。

避免产生“编辑一下模型 → 摄像头重启 → 面捕初始化 → 状态闪烁”的问题。

### 4.3 鼠标追踪只在“真正拖模型”期间临时抑制

当前 `syncMouseTrackingSubscription()` 使用：

```js
&& !adjustmentEnabled
```

应删除这一条件，改为引入更精确的：

```text
modelDragActive
```

推荐行为：

```text
模型编辑已打开，但用户没按住模型
→ 鼠标追踪正常

用户按住左键拖动模型
→ modelDragActive = true
→ 临时停止鼠标位置驱动

pointerup / pointercancel
→ modelDragActive = false
→ 立即恢复鼠标追踪
```

这样不会出现用户为了调整位置而让 Miku 的头眼追着正在拖动模型的鼠标乱跑，同时也不会让整个编辑模式失去追踪能力。

如果此时肢体追踪开启且面部 feature 有效，该 feature 可以持续工作，不受 `modelDragActive` 影响。

## 5. 肢体追踪面部 feature 的镜像统一规范

## 5.1 产品定义：像照镜子一样

不要以“模型参数 L/R 名字”作为产品定义，而以**用户看到的视觉结果**为准。

最终规范：

| 用户动作 | 桌宠视觉反应 |
|---|---|
| 抬头 | 桌宠抬头 |
| 低头 | 桌宠低头 |
| 向用户左侧转头 | 桌宠画面向右侧转 |
| 向用户右侧转头 | 桌宠画面向左侧转 |
| 向左侧歪头 | 桌宠画面向右侧歪头 |
| 左眼眨眼 | 桌宠画面右侧的眼睛眨眼 |
| 右眼眨眼 | 桌宠画面左侧的眼睛眨眼 |
| 左眉抬起 | 桌宠画面右侧眉毛抬起 |
| 右眉抬起 | 桌宠画面左侧眉毛抬起 |
| 眼睛向左看 | 桌宠画面向右看 |
| 眼睛向右看 | 桌宠画面向左看 |
| 嘴向左歪 | 桌宠画面向右歪 |
| 张嘴/闭嘴 | 同步张嘴/闭嘴 |
| 微笑/噘嘴/鼓脸 | 同步，不翻转强度 |

一句话：

> **水平与左右非对称动作镜像；垂直动作保持同向。**

### 5.2 镜像转换只做一次

不允许：

```text
backend 翻一次 X
→ frontend 再翻一次 X
→ model config 又用负 scale
```

这种多层翻转极易导致某些参数“修好了”，另一些参数又反掉。

推荐职责：

```text
FaceTracker
→ 输出摄像头/MediaPipe 的规范语义

frontend body-tracking mirror semantic layer
→ 统一变成“镜子视觉语义”

miku-cure.config.json
→ 只负责各模型参数 ID、倍率、范围和必要的模型方向校准
```

可以在 `frontend/3d_runtime.js` 中新增：

```js
mirrorBodyFaceSemanticTarget(payload)
```

或者等价的纯函数，并为其写单元测试。

### 5.3 水平轴与 roll

镜像语义层应统一处理：

```text
headX  → 水平镜像
headZ  → 歪头镜像
bodyX  → 水平镜像
bodyZ  → 身体侧倾镜像
eyeX   → 眼球水平镜像
mouthX → 歪嘴水平镜像
```

### 5.4 垂直轴不做“镜像翻转”

以下目标视觉方向保持同向：

```text
headY：用户抬头 → 桌宠抬头
bodyY：用户上身向对应垂直方向 → 桌宠同向
eyeY：用户向上看 → 桌宠向上看
```

注意：MediaPipe 的 `pitch` 正负和 Live2D `ParamAngleY` 的正负不一定天然一致。因此“垂直不镜像”不等于“代码一定乘 +1”。最终应以视觉验收结果为准，在模型 binding 的 `scale` 上做一次校准，使**正向语义最终呈现为抬头**。

两个模型必须使用相同的视觉规范。

### 5.5 左右眼和左右眉按“屏幕侧”验收

不要仅凭：

```text
ParamEyeLOpen
ParamEyeROpen
```

的字母判断最终左右，因为 Live2D 的 L/R 通常是角色自身左右，而用户说的“右眼”更接近画面视觉左右。

施工时对两个模型分别做一次可视校准：

```text
只把某一个 eye-open 参数写 0
→ 记录画面哪一侧眼睛真正闭合
```

然后锁定：

```text
用户左眼
→ 桌宠画面右侧眼睛

用户右眼
→ 桌宠画面左侧眼睛
```

眉毛同样处理。

由于 `miku` 与 `樱花miku` 来自同一参数体系，预计映射一致，但验收不能只靠参数名推断。

## 6. 状态仲裁与 UI 状态必须分离

保留两个不同概念：

### 用户选择状态

```text
mouseEnabled
bodyEnabled
watermarkEnabled
```

用于：

- Emoji 是否有红线；
- “当前追踪”主文字；
- 配置持久化。

### 实际运行状态

```text
activeTrackingSource = face | mouse | none
faceFeatureHealthy
faceFeatureReason
faceFeatureLastValidAt
```

用于：

- 3 秒丢脸 fallback；
- 400 ms 恢复稳定；
- 是否订阅桌面光标；
- tooltip/诊断；
- 日志与自动测试。

禁止再用 `activeTrackingSource === 'none'` 直接把主 UI 写成“当前追踪：关闭”。

真人初验结果：整体头姿、眼球等无明显问题；发现并修正两项方向问题：

- 左右眼：交换 `leftOpen/rightOpen` 到 Cubism `R/L`；
- 歪嘴：`mouthX` 取消额外反号，直接使用 Face Landmarker 语义值。

同时定位启动时偶发“肢体追踪已开启但实际回退鼠标”的竞态：启动早期 `clearRuntime` 产生的旧 `set_face_tracking=false` 可能进入 pending queue，而模型加载后的新 `true` 先发出，随后旧 `false` 在 `configSynced` 后被 flush，反向覆盖新状态。修复为：

1. `set_face_tracking` 是 level-triggered 状态，只在 pending queue 中保留最新一条；
2. `configSynced=false` 时即使 WS 已认证，也不直接发送 tracking 状态；
3. `backend_ready` 仅当 `trackingState.modelReady=true` 时才根据模型能力主动同步；
4. Live2D 模型 ready 后仍通过原 tracking event 同步保存的 `bodyEnabled`。
