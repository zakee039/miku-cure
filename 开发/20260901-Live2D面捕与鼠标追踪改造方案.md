# Miku Cure Live2D 面捕、精细表情与鼠标追踪改造方案（最终版）

> 日期：2026-09-01  
> 基线版本：v1.2.1 / `1374a40`  
> 项目：`E:\project\miku cure`  
> 状态：已完成施工前审查，作为后续施工与验收基线  
> 本文确定产品行为、状态机、架构和验收标准；施工按本文执行。

---

## 1. 最终结论

经模型资源与现有代码核查，两个 Live2D 模型 `miku`、`樱花miku` 都已经具备较完整的实时面捕参数基础，包含头部、身体、眼睛、眉毛、嘴型以及鼓脸、噘嘴、吐舌等精细参数。当前 Miku Cure 尚未真正接入连续面捕；现有摄像头链路主要是约 2 Hz 的情绪识别，鼠标跟随则被项目主动关闭。需要特别区分“模型有参数”和“检测器能提供输入”：MediaPipe Face Landmarker 的正式 52 项 blendshape 不包含 `tongueOut`，因此吐舌只作为未来可选扩展，不属于本次硬验收。

本次方案最终确定为 **三个相互独立的用户功能 + 一个运行时仲裁器**：

1. **鼠标追踪**：Live2D 模型特性，放入“模型编辑”内部，默认开启。
2. **面部捕捉**：Live2D 模型特性，放入“模型编辑”内部，默认关闭；一个开关即包含头部、眼球、眨眼、眉毛、嘴型及精细表情驱动，不再拆成多个用户开关。
3. **表情识别**：用户情绪识别功能，仍由主页面表情状态区域控制，可独立开启/关闭；与面捕完全解耦。
4. **Tracking Arbiter（追踪仲裁器）**：保证鼠标追踪与面捕在同一时刻只有一个实际写入 Live2D 追踪参数，并实现面捕失效时自动回退鼠标追踪。

最重要的原则是：

> **表情识别与面捕可以同时开启，互不依赖；鼠标追踪与面捕可以同时处于“已启用”状态，但实际驱动源互斥。面捕健康时由面捕驱动，面捕失效时自动回退到已启用的鼠标追踪。**

这里的“互斥”是 **实际驱动源互斥**，而不是强制两个按钮 UI 只能亮一个。否则无法实现“面捕失效时自动回退鼠标”的需求。

## 2. 四个状态必须严格区分

后续代码中禁止继续把“摄像头开关”“表情识别”“面捕”“鼠标跟随”混成同一个概念。

### 2.1 鼠标追踪 `mouseTrackingEnabled`

- 类型：模型能力 / 模型显示特性。
- UI：模型编辑内部按钮。
- 默认：**开启**。
- 摄像头：不需要。
- 作用：眼球优先跟随鼠标，头部轻微跟随，身体弱跟随。
- 当面捕正在正常工作时：进入待机，不写模型参数。
- 当面捕失效时：若该开关仍开启，自动接管模型。

### 2.2 面部捕捉 `faceTrackingEnabled`

- 类型：模型能力 / 模型显示特性。
- UI：模型编辑内部按钮。
- 默认：**关闭**。
- 摄像头：需要。
- 一个开关统一包含：
  - 头部 X/Y/Z；
  - 身体姿态跟随；
  - 眼球 X/Y；
  - 左右眼开合与真实眨眼；
  - 眉毛高度/形态；
  - 嘴张开；
  - 微笑/嘴型；
  - 模型与检测器同时支持时的鼓脸、噘嘴、歪嘴等精细表情；吐舌预留参数，但本期不承诺检测。
- 不把“精细表情”另做第二个用户开关。

### 2.3 表情识别 `emotionRecognitionEnabled`

- 类型：用户状态识别能力，不属于 Live2D 面捕。
- UI：主页面现有表情状态区域，点击即可开启/关闭。
- 默认：**保持当前产品行为，默认开启**。
- 摄像头：需要，但与面捕共享同一 Camera Service。
- 作用：
  - 识别 `happy / sadness / surprise / anger / fear / disgust / contempt / neutral`；
  - 更新主页面表情徽标与置信度；
  - 保留情绪日志、报告、主动关怀等现有业务；
  - 可继续触发模型的高层情绪反应，但不得覆盖面捕拥有的连续追踪参数。

关闭表情识别后：

- 不再执行 PyTorch 情绪分类；
- 不再产生新的 `emotion_update`；
- 不影响鼠标追踪；
- 不影响面部捕捉；
- 如果面捕仍开启，摄像头继续工作；
- 如果面捕也关闭，Camera Service 才释放摄像头。

### 2.4 实际追踪源 `activeTrackingSource`

运行时只允许：

- `face`
- `mouse`
- `none`

三个状态之一。

禁止出现鼠标和面捕同时直接写 `ParamAngleX`、`ParamEyeBallX` 等参数。

## 3. 默认启动状态

正式默认值确定为：

| 功能 | 默认状态 | UI 位置 |
|---|---:|---|
| 鼠标追踪 | 开 | 模型编辑 |
| 面部捕捉 | 关 | 模型编辑 |
| 表情识别 | 开 | 主页面表情徽标 |
| 模型自然呼吸/基础 Idle | 开 | 内部行为 |

因此默认启动后的体验是：

```text
模型：跟随鼠标
摄像头：用于表情识别
表情识别：正常记录/展示用户情绪
面捕：不启用
```

如果用户在主页面点击表情徽标关闭表情识别，而没有开启面捕：

```text
模型：仍然跟随鼠标
摄像头：释放
表情识别：关闭
面捕：关闭
```

如果此时用户进入模型编辑并开启面捕：

```text
模型：面捕优先驱动
摄像头：重新打开，供 FaceLandmarker 使用
表情识别：仍然关闭，不会因为面捕而自动恢复
鼠标追踪：保持已启用，但进入备用状态
```

## 4. 鼠标追踪与面捕的最终互斥/回退规则

### 4.1 优先级

固定为：

```text
有效面捕 > 鼠标追踪 > Live2D 自然 Idle
```

### 4.2 状态表

| 鼠标开关 | 面捕开关 | 面捕当前有效 | 实际驱动 |
|---:|---:|---:|---|
| 关 | 关 | - | `none` |
| 开 | 关 | - | `mouse` |
| 关 | 开 | 是 | `face` |
| 关 | 开 | 否 | `none` |
| 开 | 开 | 是 | `face` |
| 开 | 开 | 否 | `mouse` |

这张表就是实现时的唯一判定标准。

### 4.3 为什么两个按钮不应强制 UI 互斥

用户开启面捕后，鼠标追踪按钮可以继续显示为开启，含义是：

> 鼠标追踪能力已启用，但当前由更高优先级的面捕占用驱动权；鼠标处于备用状态。

UI 可以通过状态文字显示：

- `鼠标追踪 · 使用中`
- `鼠标追踪 · 备用`
- `面捕 · 使用中`
- `面捕 · 未检测到人脸`

这样既满足两个独立开关，也能实现自动回退。

### 4.4 面捕失效判定

不能一帧没检测到脸就立刻切换，否则会在遮挡、眨眼或快速转头时抖动。

建议：

- 连续丢失人脸约 **3 秒** 后，将面捕标记为 `lost`；
- 若鼠标追踪开启，平滑切换到 `mouse`；
- 重新检测到人脸后，连续稳定约 **300～500 ms** 再恢复 `face`；
- 从鼠标回面捕时做 150～300 ms 插值，避免头部瞬间跳变。

具体阈值可测试后微调，但必须有迟滞机制。

丢脸宽限期内不得把最后一帧僵硬保持 3 秒：前 200 ms 可短暂保持，随后由 Face Controller 将追踪值平滑衰减至中性；达到丢失阈值后再由 Arbiter 切换到鼠标或 `none`。

### 4.5 摄像头异常也属于面捕失效

以下情况都触发同一回退逻辑：

- 摄像头被拔出；
- 摄像头权限失败；
- FaceLandmarker 初始化失败；
- 连续读取失败；
- 长时间无脸；
- 推理线程异常；
- 模型不支持面捕映射。

只要鼠标追踪开关仍为开启，桌宠都应继续自然跟随鼠标，而不是冻结。

## 5. 表情识别与面捕必须完全解耦

这是本方案与旧结构最大的变化。

### 5.1 两者虽然都使用摄像头，但不是同一个功能

```text
                        Camera Service
                             │
              ┌──────────────┴──────────────┐
              │                             │
              ▼                             ▼
    Emotion Recognition             Face Landmarker
          ~2 Hz                       15~20 Hz
              │                             │
              ▼                             ▼
    emotion_update                 face_tracking
              │                             │
       情绪语义/日志/关怀              连续 Live2D 参数
```

### 5.2 可以任意组合开启

必须支持四种组合：

| 表情识别 | 面捕 | 摄像头 | 行为 |
|---:|---:|---|---|
| 关 | 关 | 关闭 | 无视觉识别 |
| 开 | 关 | 低频工作 | 只做情绪识别 |
| 关 | 开 | 高频工作 | 只做面捕，不做情绪分类 |
| 开 | 开 | 高频工作 | 共用摄像头，同时运行两条推理链 |

### 5.3 面捕开启不能偷偷开启表情识别

例如用户已经在首页点击关闭表情识别，再到模型编辑开启面捕：

- `emotionRecognitionEnabled` 必须继续保持 `false`；
- 面捕只申请摄像头和 FaceLandmarker；
- 不得重新启动情绪分类模型；
- 主页面表情徽标继续显示“识别关闭”。

反过来也一样：关闭面捕不能关闭表情识别。

### 5.4 表情识别对模型的高层反应不得污染面捕参数

现有 `Miku3D.setEmotion()` 可以继续作为高层情绪反应入口，但需要加入参数仲裁。

原则：

- Face Tracking 拥有连续的标准面捕参数；
- 情绪表达式可以改变模型专属效果参数，例如脸红、圈圈、附加装饰等；
- 如果某 `.exp3.json` 同时修改了眼睛、嘴巴、眉毛等正在由面捕驱动的标准参数，则面捕值最终覆盖这些重叠参数；
- 用户主动触发的强动作仍可高于普通情绪表达式。

因此“同时开表情识别 + 面捕”不会造成嘴型、眼睛、头部互相抢值。

## 6. UI 最终设计

## 6.1 主页面：表情徽标只控制表情识别

现有主页面表情徽标继续保留，但语义从“摄像头开关”改为：

> **表情识别开关**

点击：

- 开 → 关：停止 EmotionDetector 消费帧；
- 关 → 开：恢复 EmotionDetector；
- 不直接决定摄像头物理开关。

状态建议：

- `😊 开心 86%`：识别开启且有结果；
- `👽 未检测到人脸`：识别开启但当前无人脸；
- `🔌 表情识别已关闭`：用户关闭；
- `⚠ 摄像头不可用`：识别需要摄像头但 Camera Service 失败。

## 6.2 模型编辑：新增两个模型特性按钮

模型编辑区域增加：

### 按钮 A：鼠标追踪

建议图标：`🖱` 或现有 UI 风格的鼠标图标。

状态：

- 开启 / 使用中；
- 开启 / 备用；
- 关闭。

默认：开启。

### 按钮 B：面部捕捉

建议图标：人脸轮廓/摄像头人脸图标。

状态：

- 关闭；
- 初始化中；
- 使用中；
- 未检测到人脸；
- 摄像头不可用；
- 模型不支持。

默认：关闭。

### 6.3 模型编辑中显示“当前追踪源”

建议增加一行小状态文字，不需要再加第三个按钮：

```text
当前追踪：鼠标
当前追踪：面捕
当前追踪：鼠标（面捕暂时丢失）
当前追踪：关闭
```

这样用户能直接理解两个按钮都亮时为什么当前只有一种驱动。

### 6.4 这些按钮是模型特性，不放到通用设置页

用户已经明确要求追踪属于模型能力，因此：

- 不在普通设置页增加“追踪模式”下拉框；
- 不在首页增加鼠标/面捕按钮；
- 两个按钮仅在 Live2D 模型编辑界面出现；
- 模型不支持对应能力时可以隐藏或禁用按钮。

## 8. 鼠标追踪实现

### 8.1 不恢复 `autoInteract: true`

继续保留：

```js
Live2DModel.from(manifest, {
  autoInteract: false,
  autoUpdate: true,
})
```

原因是 canvas 已承载：

- 摸头；
- 点脸；
- 手臂点击；
- 双击；
- 画圈；
- 模型编辑拖动；
- 缩放。

直接恢复库级自动交互容易与现有事件体系冲突。

### 8.2 使用独立 `MouseTrackingController`

Electron 主进程使用 `screen.getCursorScreenPoint()` 获取桌面级鼠标位置，在鼠标追踪实际激活时以约 30 Hz 提供位置。

前端将光标位置相对当前桌宠窗口/模型视觉中心归一化，再送入 Live2D FocusController 或等价的安全参数层。

建议首版强度：

- 眼球：0.70～0.80；
- 头部：0.40～0.50；
- 身体：0.10～0.20。

效果应是“眼睛明显跟随，头轻微跟随，身体只有一点惯性”，避免整个人机械追鼠标。

### 8.3 编辑模式暂停追踪写入

当用户正在拖动/缩放模型时：

- 暂停鼠标追踪写入；
- 暂停面捕写入；
- 保留最后追踪源状态；
- 退出编辑操作后平滑恢复。

避免“我拖模型，模型头又跟着光标跑”的体验冲突。

## 9. 面捕实现：一个开关包含完整精细表情

### 9.1 FaceLandmarker

使用当前 MediaPipe 0.10.35 已支持的 `FaceLandmarker`，新增正式离线模型资产 `face_landmarker.task`。

正式发行包不得依赖首次运行联网下载。资产必须固定官方来源、版本与 SHA-256，启动和打包时同时校验存在性、摘要与合理大小。

初始化要求：

- `running_mode=LIVE_STREAM`，时间戳使用单调递增毫秒值；
- `num_faces=1`，以使用单人平滑追踪；
- `output_face_blendshapes=true`；
- `output_facial_transformation_matrixes=true`，头部三轴从变换矩阵求取；
- 忙碌时允许丢弃中间帧，只处理最新帧，禁止推理队列持续增长。

### 9.2 推理频率

建议：

- 摄像头采集：20～30 FPS；
- FaceLandmarker：15～20 Hz；
- EmotionDetector：仍维持约 2 Hz；
- 前端渲染：requestAnimationFrame；
- 使用插值把 15～20 Hz 面捕结果平滑到渲染帧率。

### 9.3 面捕输出

后端发送归一化后的语义参数，而不是直接把 MediaPipe 原始 478 点全部塞给前端。

例如：

```json
{
  "type": "face_tracking",
  "valid": true,
  "head": { "x": 0.12, "y": -0.08, "z": 0.03 },
  "body": { "x": 0.04, "y": -0.02, "z": 0.01 },
  "eyes": {
    "x": 0.31,
    "y": -0.14,
    "leftOpen": 0.92,
    "rightOpen": 0.88
  },
  "brows": {
    "leftY": 0.18,
    "rightY": 0.21,
    "form": 0.07
  },
  "mouth": {
    "open": 0.24,
    "smile": 0.35,
    "pucker": 0.02,
    "x": -0.05
  },
  "cheekPuff": 0.01
}
```

`tongueOut` 不在 Face Landmarker 的正式 52 项输出中，不进入本期协议；模型的 `Paramtushe` 仅保留为未来自定义检测器扩展点。

前端再依据当前模型配置把语义量映射到对应 Live2D 参数。

### 9.4 精细表情属于同一面捕功能

产品层不分：

- “基础面捕”；
- “精细表情”；
- “嘴部捕捉”；
- “眼球捕捉”。

只有一个“面部捕捉”按钮。

开发内部可以分阶段接通头部、眼睛、嘴、眉毛等参数，但正式验收时该开关必须作为一个完整功能交付。

## 10. Camera Service 必须改成共享资源管理器

现有 `toggle_camera` 语义不能继续使用，因为摄像头不再等于表情识别。

建议引入：

```text
CameraService
  ├─ emotion consumer
  └─ face-tracking consumer
```

生命周期：

```text
needCamera = emotionRecognitionEnabled || faceTrackingEnabled
```

- 两者都关：关闭摄像头；
- 任一开启：保持摄像头；
- 只有表情识别：可低频采样；
- 面捕开启：摄像头提升到面捕所需帧率；
- 表情识别从高频帧流中每约 500 ms 取最新一帧即可，不额外打开第二路摄像头。

禁止同一个物理摄像头被两个 `cv2.VideoCapture` 实例重复打开。

### 10.1 帧快照与消费者游标

共享帧不能继续使用“某个消费者读取后清空”的语义。Camera Service 每次采集发布不可破坏的最新快照：

```text
FrameSnapshot(sequence, capturedAtMonotonic, image)
```

- `sequence` 每采集一帧递增；
- 每个消费者独立保存 `lastSequence`，只处理新帧；
- 快照始终只保留一份最新图像，避免队列积压；
- 从 2 FPS 提升到 20～30 FPS 必须通过线程安全的动态采集配置完成，不能只修改一个不会被当前采集循环重新读取的字段。

### 10.2 物理状态、用户意图与健康状态分离

必须分别维护：

- 用户意图：`emotionRecognitionEnabled`、`faceTrackingEnabled`；
- 物理摄像头：`cameraConnected`；
- 推理健康：`emotionHealthy`、`faceHealthy`；
- 临时挂起：`cameraSuspended` 与原因。

用户上次关闭表情识别后，下次启动不得先短暂打开摄像头再等待前端关闭。主进程必须在启动后端前传入已持久化意图，或让后端默认不申请摄像头并等待认证后的首次状态同步。

### 10.3 独占摄像头租约

设置页训练采集会通过浏览器 `getUserMedia()` 独占同一个摄像头，LoRA 训练也会临时停止推理。两条路径必须使用可恢复的 suspend/lease 机制：

- 获取租约时暂停物理摄像头和两个消费者，但不修改用户开关；
- 释放租约后根据当前消费者集合重新决定是否打开摄像头；
- 异常、窗口关闭和训练失败都必须在 `finally` 中释放租约；
- 禁止用“记住旧物理 connected 布尔值后直接 start/stop”恢复状态。

## 11. 追踪仲裁器

建议新增 `Live2DTrackingController`，只允许它决定谁拥有标准追踪参数。

### 11.1 源状态

```text
mouseEnabled
faceEnabled
faceHealthy
editingModel
```

核心逻辑：

```text
if editingModel:
    active = none-temporary
else if faceEnabled and faceHealthy:
    active = face
else if mouseEnabled:
    active = mouse
else:
    active = none
```

### 11.2 参数所有权

Tracking Controller 负责的标准参数：

- `ParamAngleX/Y/Z`
- `ParamBodyAngleX/Y/Z`
- `ParamEyeBallX/Y`
- `ParamEyeLOpen/ROpen`
- `ParamBrow*`
- `ParamMouthForm`
- `ParamMouthOpenY`
- 模型声明的精细面部参数

鼠标模式只写其中头/眼/少量身体参数，不写眉毛和嘴。

面捕模式可写完整集合。

### 11.3 与动作系统的优先级

建议最终参数优先级：

```text
模型基础 Idle / Physics
        ↓
高层情绪表达式
        ↓
Tracking（鼠标或面捕）
        ↓
用户主动动作 / 强制动作覆盖
        ↓
水印等固定安全覆盖
```

但需要按“参数集合”而不是粗暴按整层覆盖：

- 面捕优先掌握标准脸部追踪参数；
- 投喂、比心、唱歌等动作可拥有自己的专属动作参数；
- 用户主动动作如确实需要临时接管某个脸部参数，可声明该参数的短时 override；
- 动作结束后平滑恢复 Tracking 当前值。

每帧正式写入顺序固定为：

```text
resetParameters → Tracking 参数 → 动作声明的临时覆盖参数 → 水印/固定安全覆盖 → coreModel.update
```

动作不能默认接管整张脸，只有在模型配置中显式列出的参数才允许短时覆盖 Tracking。

## 14. 协议建议

旧：

```text
toggle_camera
```

应逐步废弃为更清楚的语义协议：

```text
set_emotion_recognition { enabled: bool }
set_face_tracking       { enabled: bool }
get_camera_status
get_tracking_status
```

后端状态可返回：

```json
{
  "type": "tracking_status",
  "faceEnabled": true,
  "faceHealthy": false,
  "mouseEnabled": true,
  "activeSource": "mouse",
  "reason": "face_lost"
}
```

鼠标开关本身主要属于前端模型特性，可由前端持久化；如果统一状态管理更方便，也可以由主进程同步，但不需要后端参与鼠标坐标计算。

## 15. 持久化规则

建议按“模型 ID”保存两个模型特性：

```text
miku-character-tracking[modelId].mouseEnabled
miku-character-tracking[modelId].faceEnabled
```

默认值：

```text
mouseEnabled = true
faceEnabled = false
```

表情识别仍是应用级设置：

```text
emotionRecognitionEnabled = true
```

主进程配置白名单必须增加这两类持久化键，并在启动后端前决定初始 `emotionRecognitionEnabled`。模型切换时使用 generation 丢弃旧模型的迟到结果，并按新模型能力/偏好重新同步 `faceTrackingEnabled`。

这样更换模型后，每个模型可以拥有自己的追踪偏好和能力。

如果后续新增不支持面捕的 MMD/Live2D 模型：

- 不支持鼠标追踪 → 隐藏/禁用鼠标按钮；
- 不支持面捕 → 隐藏/禁用面捕按钮；
- 不影响主页面表情识别，因为表情识别属于用户状态识别而不是模型能力。

## 16. 验收矩阵

### A. 默认行为

- [ ] 首次启动鼠标追踪默认开启。
- [ ] 面捕默认关闭。
- [ ] 表情识别默认沿用现状开启。
- [ ] 模型眼睛/头部可自然跟随全桌面鼠标。

### B. 表情识别独立性

- [ ] 点击主页面表情徽标可单独关闭表情识别。
- [ ] 关闭表情识别后鼠标追踪不受影响。
- [ ] 关闭表情识别后仍可独立开启面捕。
- [ ] 面捕开启不能自动打开表情识别。
- [ ] 面捕关闭不能关闭表情识别。

### C. 面捕完整性

- [ ] 面捕一个开关即可驱动头部三轴。
- [ ] 眼球方向可跟随真人。
- [ ] 左右眼开合与眨眼可跟随真人。
- [ ] 眉毛可连续变化。
- [ ] 嘴张开与嘴型可连续变化。
- [ ] 模型支持且 Face Landmarker 有输入的鼓脸/噘嘴/歪嘴等精细参数可工作。
- [ ] `Paramtushe` 保留未来扩展，但本期不把吐舌列为交付失败条件。
- [ ] 不额外暴露“精细表情”第二开关。

### D. 鼠标/面捕互斥与回退

- [ ] 鼠标与面捕不会同时写同一追踪参数。
- [ ] 面捕有效时 `activeSource=face`。
- [ ] 面捕连续丢失 3 秒后自动回退鼠标。
- [ ] 回退过程无明显跳变。
- [ ] 人脸恢复稳定后自动切回面捕。
- [ ] 如果鼠标开关关闭，面捕失效时进入 `none` 而不是偷偷启用鼠标。

### E. 两功能同时使用摄像头

- [ ] 表情识别 + 面捕可同时开启。
- [ ] 只打开一个 `VideoCapture`。
- [ ] 面捕按 15～20 Hz 工作。
- [ ] 情绪分类仍约 2 Hz，不因面捕升频而高频跑 PyTorch。
- [ ] 关闭其中一个 consumer 不影响另一个。
- [ ] 两个 consumer 都关后摄像头释放。

### F. 现有 Live2D 交互回归

- [ ] 摸头不受影响。
- [ ] 点脸不受影响。
- [ ] 双击不受影响。
- [ ] 画圈不受影响。
- [ ] 投喂/比心/唱歌等动作不受影响。
- [ ] 模型编辑拖动/缩放时追踪自动暂停。
- [ ] 动作结束后追踪平滑恢复。

### G. 失败路径

- [ ] 无摄像头时面捕按钮显示明确错误。
- [ ] 摄像头拔出后自动回退鼠标。
- [ ] FaceLandmarker 模型缺失时不影响鼠标和普通 UI。
- [ ] 表情识别模型错误不影响面捕。
- [ ] 面捕错误不影响表情识别。
- [ ] 用户关闭表情识别后重启，启动阶段不会短暂打开摄像头。
- [ ] 摄像头重新插入后，在仍有消费者时按有界退避自动恢复。

### H. 数据与并发

- [ ] 两个消费者不会重复处理同一 `sequence`。
- [ ] 情绪消费者读取帧不会清空或饿死面捕消费者。
- [ ] 面捕忙碌时丢帧而不积压。
- [ ] 设置页训练采集取得独占租约后，结束或失败都恢复原用户意图。
- [ ] 模型切换后旧 generation 的面捕结果不会写入新模型。

### I. 性能与发行

- [ ] 在指定参考机器上记录面捕 FPS、P95 推理延迟、CPU 与内存占用。
- [ ] `face_landmarker.task` 的 SHA-256、大小、来源与许可记录可追溯。
- [ ] 便携包缺失或损坏 `.task` 时构建失败。
- [ ] 启动环境检查能报告 `.task` 缺失/损坏，但普通 UI 与鼠标追踪仍可运行。
- [ ] 两个内置 Live2D 模型只有在再分发授权允许时才进入发行包；否则能力配置仅随用户模型本地使用。

## 17. 施工顺序

虽然产品上面捕只有一个开关，但开发仍建议分内部阶段，以降低风险。

### Phase 1：追踪状态机 + 鼠标追踪

- 模型编辑增加两个按钮与追踪源状态；
- 实现模型级持久化；
- 实现桌面鼠标追踪；
- 建立 Tracking Arbiter；
- 先用 mock faceHealthy 验证 face > mouse > none 切换。

### Phase 2：Camera Service 解耦

- 主页面表情徽标从 `toggle_camera` 改为 `set_emotion_recognition`；
- Camera Service 改多 consumer；
- 加入帧序号、独立消费者游标、动态 FPS 与断线重试；
- 把设置页训练采集和 LoRA 训练改为独占租约；
- 先保证“表情关、面捕开”与“表情开、面捕关”两种路径都正确。

### Phase 3：FaceLandmarker 完整接入

- 加入离线 `face_landmarker.task`；
- 接头部、眼球、眨眼、眉毛、嘴部和 Face Landmarker 可提供的精细表情；
- 完成丢脸回退与恢复；
- 完成参数仲裁。

### Phase 4：双模型标定 + 全回归

- 分别校准 `miku` 与 `樱花miku`；
- 跑完整前端/后端自动测试；
- 做真实摄像头长时间测试；

正式发布时不暴露 Phase 2/3 的半成品状态；“面部捕捉”开关只有在完整头眼嘴眉精细参数链路达到验收门槛后才视为完成。

## 18. 最终产品行为一句话

> **表情识别负责“理解用户是什么情绪”，面捕负责“让 Miku 模仿用户的脸”，鼠标追踪负责“没有可靠面捕时让 Miku 看向用户的鼠标”。表情识别与面捕彼此独立，面捕与鼠标追踪由仲裁器互斥驱动，并在面捕失效时自动回退鼠标。**

这三者的产品入口固定为：

```text
主页面表情徽标
└─ 表情识别 开/关

模型编辑
├─ 鼠标追踪 开/关（默认开）
└─ 面部捕捉 开/关（默认关，包含精细表情）
```

该结构作为后续实现的最终基线。
