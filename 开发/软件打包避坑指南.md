# Miku Cure 软件打包避坑指南

本文档记录了在项目开发和打包过程中遇到的核心踩坑经验，以防止后续在打包环节再次绕弯路。

## 1. PyInstaller 打包陷阱 (`--onefile` vs `--onedir`)
在使用 PyInstaller 打包 Python 后端时，切忌使用 `--onefile` 打包为单文件可执行程序！
- **问题**：`--onefile` 会在每次程序启动时，将内含的庞大虚拟环境和依赖（数百 MB）解压到系统临时目录（如 `AppData/Local/Temp`）。这会导致后端启动时间长达数秒甚至十几秒，致使前端因为超时而认为后端挂掉。
- **正解**：必须使用 `--onedir`（文件夹模式），这样程序可以直接在磁盘上执行已解压好的二进制文件，实现 **0秒光速启动**。

## 2. Electron 幽灵缓存污染 (`LocalStorage`)
Electron 应用默认会在用户的 `%APPDATA%` 目录下保留基于应用名的系统级浏览器缓存数据。
- **问题**：如果在开发期间使用了 `localStorage` 来保存诸如用户名、已选择的模型、甚至是认主状态，那么在打包成独立的 ZIP 给用户时，由于应用名相同，打包后的应用会在用户的电脑上离奇地读取到开发者或以前残余的个人数据（称为“幽灵缓存”）。
- **正解**：对于旨在 100% 绿色便携发行的应用，**必须禁用或完全抛弃 `localStorage`**，将所有的系统配置和用户隐私状态落盘保存至应用自带的本地工作目录中（例如本项目中的 `user/config.json`）。

## 3. 打包后资源路径解析 (`__dirname` 失效)
在开发环境下，`__dirname` 会完美指向源代码所在的真实目录。但在打包后（尤其是开启了 ASAR 封装的情况下），`__dirname` 会指向一个无法被外部程序（如 Python 后端、或者系统文件 IO 操作）正常访问的虚拟压缩包内部（`app.asar`）。
- **问题**：如果你使用 `path.join(__dirname, '../backend')` 试图去寻找外部文件，打包后必定报找不到文件的错误。
- **正解**：必须使用 `app.isPackaged` 判断环境。打包后，使用 `path.dirname(process.execPath)` 获取 `.exe` 所在的外层真实目录，从而反推出外部资源的路径。

## 4. 跨进程通信与前端报错拦截
当基于子进程（`child_process`）启动后端时，后端的崩溃或报错默认是静默的。前端若使用 `fetch` 向可能处于挂掉状态的本地接口发请求，若未做充分的 `catch` 或网络检测，则会引发 Uncaught Exception 导致界面白屏。
- **正解**：严格在子进程层面绑定 `.on('error')` 和 `.on('exit')`，并在任何网络请求或 websocket 初始化时增加稳妥的 try-catch，以便给出友好的 "系统未启动" 提示。
